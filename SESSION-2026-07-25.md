## Operating rules, read before touching anything
1. **Never edit live files directly.** Stage to `staging/` (same relative paths) then run `./deploy.sh <files>`. It gates: syntax check, EDI transmit-quiet wait (up to 15 min so a deploy never lands mid-send), git snapshot + .bak, promote, restart, smoke-test.js. A direct edit skips every safety net.
2. **Reliability degrades to STALE, never to WRONG.** Any scraper that fails keeps the last-known good value flagged stale and never overwrites good data with a partial or zeroed pull. Alerts fire above a failure threshold. Preserve this posture in anything you add.
3. **"Value Remaining" is Amazon's own number.** Per-PO remaining balance now comes from Amazon's "Available amount" on each PO detail page, scraped into payee-po-details.spark.json. Do not reintroduce the old computed (ceiling minus consumed minus pending) figure as the headline number; it drifted and went negative.
4. **Site codes are normalized to the canonical Amazon token** (DBU3 PKG HEMPSTEAD3 becomes DBU3) before any by-site grouping. Keep that or the by-site view fragments.
5. **Ambiguous POs are flagged for manual review, never silently hidden.** The snow filter used to drop any PO it could not classify; now those surface for Edwin to classify.
6. **PO Funds is Amazon-only** (customers C-00403 and C-00566).

## What changed this window (all live on prod)

### 1. Authoritative Value Remaining (payee-po-detail-scraper.js, new)
SearchOpenPOs only returns the ORIGINAL po amount, never the live remaining. Amazon exposes the true, quantity-enforced remaining only on each PO detail page: payeecentral.amazon.com/PurchaseOrder/Details?poNumber=X (singular "PurchaseOrder"), which server-renders "Available amount $X USD" plus Ship To site and line-item description.
- New scraper walks every open PO detail page (concurrency 3, ~1,118 pages), writes payee-po-details.spark.json. Reuses payee-scraper launchBrowser / ensureLoggedInContext (now exported).
- Parse gotchas: negatives show in accountant parens "($760.28 USD)" = -760.28. Masked POs show "Available amount --" (Amazon will not disclose; recorded masked:true, not retried, not a failure).
- po-ledger rows carry amazonAvailable / computedAvailable / availableSource / availableStale. 1,068 of 1,118 open POs are Amazon-sourced, 50 masked.
- Scheduled in app.js doPoDetailRefresh(): 3 min after boot, then every 4 hours. Manual: POST /api/po/refresh-details.
- Semantics fix: Amazon available = ceiling minus consumed (does NOT subtract our un-submitted pending). getNeedsUpload uses drawable = amazonAvailable ?? (ceiling minus consumed) minus otherPending. getOverages flags pending > remaining, not just available < 0.

### 2. Site attribution to ~99% (81 unknown to ~8)
po-doc-watcher v6 extraction (SHIP TO token, parenthesized, Attn, desc SITE-20xx, frequency) + a learned address to site map (255 addresses) + po-email-backfill.js (pulls the PO PDF from the arclerk mailbox via Graph Mail.Read when no SharePoint doc is filed). Amazon's own Ship To site from the detail scraper is now the top automatic source, right after manual assignment. Residual ~8 are vendor-warehouse materials POs with no source, one-click Set site only.

### 3. Site normalization (normalizeSite in po-ledger.js)
Collapses any Sage ship-to string that starts with a canonical Amazon token to just the token. Applied to the site vote, ledger rows, and needs-upload / uploaded / resubmission rows. Rows keep siteCodeRaw.

### 4. Service classification review + manual override
POs whose doc has no service keyword default to serviceType 'other' and were being hidden by the snow filter (surfaced as "DNK5 is missing invoices tied to 2D-19117605"; also caught real misses like 2D-19133276 "SNOWEX CONTAINER INSTALLATION"). Now flagged needsServiceReview (15 POs / $242k pending). Pending by Site shows an amber banner + a Review and classify modal; saving POSTs /api/po/:po/service. db.js purchase_orders.service_type + setPoService(); serviceType chain = manual override wins, else classifyService(doc).

### 5. Roll placeholder into a real PO
Placeholders (NEEDED KRB5 and similar) are not real POs, just the Sage PO-field text pending invoices group under. Reassigning already empties them; this added a one-click Roll into PO / Roll all that bulk-reassigns every invoice under the placeholder with an Amazon-live overage preview (warn but allow). Backend /api/po/reassign-bulk already existed. po-ledger flags isPlaceholder.

### 6. Pending by Site accuracy
Pending is grouped by the INVOICE's own Sage site, not the PO site (fixed the KRB5 undercount 8 to 11). serviceType classifier with per-PO chips; snow toggle aligned to serviceType.
